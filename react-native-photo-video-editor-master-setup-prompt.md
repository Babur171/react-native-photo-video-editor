## Product objective

This package will eventually provide a full-screen native photo and video editor for React Native apps. The initial milestone must establish a reliable native library architecture and a runnable example app. It must include a small working native contract, but it must not attempt to build the complete editing engine in this milestone.

The final consumer experience should eventually look like this:

```ts
import {
  openEditor,
  cancelExport,
  addExportProgressListener,
  type EditorOptions,
  type EditorResult,
} from 'react-native-photo-video-editor';

const result = await openEditor({
  source: {
    uri: 'file:///path/to/video.mp4',
    type: 'video',
  },
  features: {
    crop: true,
    rotate: true,
    trim: true,
    mute: true,
    text: true,
    filters: true,
  },
  export: {
    quality: 'high',
    format: 'mp4',
  },
});
```

For this setup milestone, `openEditor()` may use a native placeholder implementation that validates the request and returns a typed result. Clearly document that actual editing and export functionality is planned for later milestones.

## Non-negotiable technical decisions

- Target React Native Android and iOS only.
- Use a Turbo Native Module and React Native Codegen.
- Use the current supported New Architecture library pattern generated by the latest stable `create-react-native-library` tool.
- Use TypeScript for all React Native-facing source code.
- Use Kotlin for all new Android code.
- Use Swift for all new iOS code.
- Include a React Native example application in the same repository.
- Use autolinking; consumers must not manually edit native project files.
- Do not add web support, Vite, React Native Web, Expo Modules, or an Expo managed example.
- Do not create a Fabric Native Component in this milestone. The editor will initially be launched as a full-screen native screen through a Turbo Module. Fabric can be evaluated later if an embeddable JSX editor view becomes a requirement.
- Do not use the legacy `NativeModules` API for the main implementation.
- Do not pass images, video frames, blobs, or base64 media over the React Native boundary. Pass file/content URIs, serializable options, progress metadata, errors, and final output metadata only.
- Keep React and React Native in `peerDependencies` for the published library.
- Avoid unnecessary runtime dependencies.
- Do not publish to npm, push to GitHub, or create commits unless explicitly requested.
- Do not overwrite an existing project or discard existing user changes.

## Phase 4: Design the TypeScript public API

Create `src/types.ts` with documented public types. Use string unions for the JavaScript-facing API and only values that can map consistently to Android and iOS.

Required public concepts:

```ts
export type MediaType = 'photo' | 'video';
export type ExportQuality = 'low' | 'medium' | 'high' | 'original';
export type ImageExportFormat = 'jpeg' | 'png' | 'webp';
export type VideoExportFormat = 'mp4' | 'mov';
export type EditorStatus =
  | 'idle'
  | 'preparing'
  | 'editing'
  | 'exporting'
  | 'completed'
  | 'cancelled'
  | 'failed';

export interface EditorSource {
  uri: string;
  type: MediaType;
  mimeType?: string;
  fileName?: string;
}

export interface EditorFeatures {
  crop?: boolean;
  rotate?: boolean;
  flip?: boolean;
  trim?: boolean;
  mute?: boolean;
  filters?: boolean;
  text?: boolean;
  stickers?: boolean;
  draw?: boolean;
}

export interface EditorTheme {
  primaryColor?: string;
  backgroundColor?: string;
  toolbarColor?: string;
  textColor?: string;
  statusBarStyle?: 'light' | 'dark';
}

export interface ExportOptions {
  quality?: ExportQuality;
  imageFormat?: ImageExportFormat;
  videoFormat?: VideoExportFormat;
  maxWidth?: number;
  maxHeight?: number;
  videoBitrate?: number;
  frameRate?: number;
  preserveMetadata?: boolean;
}

export interface EditorOptions {
  source: EditorSource;
  features?: EditorFeatures;
  theme?: EditorTheme;
  export?: ExportOptions;
  saveToGallery?: boolean;
}

export interface EditorResult {
  uri: string;
  type: MediaType;
  mimeType?: string;
  width?: number;
  height?: number;
  duration?: number;
  fileSize?: number;
  cancelled: boolean;
}

export interface ExportProgressEvent {
  jobId: string;
  progress: number;
  status: EditorStatus;
}
```

Apply JSDoc to every exported type, method, option, unit, and platform limitation. State that `duration` is milliseconds, `fileSize` is bytes, `progress` ranges from 0 to 1, dimensions are pixels, `videoBitrate` is bits per second, and `frameRate` is frames per second.

### Public methods

Expose this initial API:

```ts
openEditor(options: EditorOptions): Promise<EditorResult>
cancelExport(jobId?: string): Promise<boolean>
isAvailable(): boolean
```

Expose a listener helper with a stable cleanup contract:

```ts
const subscription = addExportProgressListener(event => {
  console.log(event.progress);
});

subscription.remove();
```

For the setup milestone, the event API can be wired but need not emit real export progress. Do not emit fake progress in production code.

### Validation defaults

Apply these JavaScript-level defaults before calling native code:

```ts
features: {
  crop: true,
  rotate: true,
  flip: true,
  trim: true,
  mute: true,
  filters: true,
  text: true,
  stickers: true,
  draw: true,
}

export: {
  quality: 'high',
  preserveMetadata: true,
}

saveToGallery: false
```

Validate at minimum:

- Options must be an object.
- `source.uri` must be a non-empty string.
- `source.type` must be `photo` or `video`.
- Width, height, bitrate, and frame rate must be positive when provided.
- Photo sources must not request video-only behavior such as trimming or muting; either normalize those flags to `false` or reject them consistently. Choose and document one policy.
- `imageFormat` and `videoFormat` must be compatible with the source type.
- Unknown enum values must produce a documented error.
